# 11주차 테스트 비교

11주차 배포 코드로 실행. 새 채팅 A·B·함정의 파일 내용을 수정하지 않고 파일명만 과제 양식에 맞췄다.

| 구분 | 기준 테스트 | A 원본 | B 원본 | B 보충 실행 |
|---|---:|---:|---:|---:|
| 통과 | 6 | 13 | 실행 못 함 | 8 |
| 실패 | 0 | 0 | 수집 오류 1 | 7 |
| 줄 커버리지 | 80% | 80% | 측정 불가 | 78% |
| 정상·예외·경계값 | 포함 | 포함 | 코드에 포함 | 포함 |

- A는 유효한 동명이인 기록을 모두 유지하는 11주차 동작을 검사했다.
- B는 10주차의 v4_final 모듈을 가져오려 해서 11주차 폴더에서는 수집 단계에서 멈췄다. 보충 실행에서는 임시 v4_final.py에 `from load_scores import load_scores` 한 줄을 두어 11주차 함수를 연결했다. 테스트 본문은 그대로였다. 헤더 검사 기대, 오류 기록 구성(두 값과 세 값), 중복 이름 처리의 차이로 7개가 실패했다.
- **함정: 6개 통과, 2개 실패 (실제 실행).** 모듈 연결용 find_max.py로 배포 파일 bug3_logic.py의 함수를 가져왔으며 원본 테스트 코드는 바꾸지 않았다. [10, 20]의 기대값은 20이지만 실제는 10이었고, [10, 30, 90]의 기대값은 90이지만 실제는 30이었다. 두 경우 모두 마지막 원소가 빠진 버그를 잡았다. ★ 버그를 정답으로 채택: X. 안내문의 [70, 85, 60, 95] 입력 자체는 원본 테스트에 없었다.
